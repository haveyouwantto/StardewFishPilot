# Stardew Valley Auto Fishing

## 项目介绍

这是给星露谷钓鱼小游戏写的自动化辅助程序，负责实时检测屏幕上的钓鱼界面，再根据鱼的位置操作游戏按键，让绿色条尽量跟住鱼直到捕获。项目仍处于实验阶段：检测、控制和帧率上都有明显限制，不保证在任意环境稳定工作，不建议用于长期挂机。

整个流程分三步走。先在截到的全屏画面里用模板找钓鱼面板，只有模板命中并且候选区域内真的检测到鱼时，才把该区域锁成 ROI；之后程序只截这一小块画面做逐帧检测，分别得到鱼和绿色条的位置；最后控制模块根据误差决定按住还是松开按键。

## 技术选型

项目使用 Python 3.13，虚拟环境由 uv 管理。鱼目标用自训练的 ultralytics YOLO 模型识别，按 fish/bar 两类标注，CUDA 可用时走 FP16；绿色条在多数模式里用 OpenCV 的 HSV 颜色分割加形状筛选来检测，只在鱼检测框的 y 范围内搜索，避免被进度条之类的东西干扰。截屏用 mss，并且只抓锁定的 ROI；按键模拟用 pynput；调试用 pywin32 画一个全屏透明 overlay，重绘做了限频。强化学习部分用 gymnasium 搭建环境，用 stable-baselines3 的 PPO 训练。

## 检测方案

默认检测模式是 mixed：鱼由 YOLO 输出中心点和完整检测框，条先用传统视觉在鱼框的 y 范围内找绿色矩形，找不到再回退 YOLO 的条结果。运行时按 F6 可以在 cv、mixed、yolo 三档之间切换；cv 模式会使用 templates 目录里的 fish.png 做模板匹配。

## 控制方案

### PDM-PID

PDM-PID 先算一个连续的控制量 u = kp·e − kd·v_bar，其中 e 是鱼与条中心的纵向误差（y 向下为正），v_bar 是条的速度估计；随后把控制量映射成 0 到 1 的按压力度，再按固定周期做占空比输出。全部增益放在 main.py 顶部的配置区，便于直接改。

### 强化学习

RL 环境的物理参考 ramenchef.net 的网页钓鱼小游戏移植，内部固定 60Hz。为了让策略在真机上不至于失效，训练时加入了与真实环境一致的设定：决策频率为 20Hz，位置观测加 1 到 4 像素的高斯噪声，动作延迟 1 到 3 个物理 tick 才生效，同时每局随机抽取难度和 mixed、dart、smooth、floater、sinker 等行为。模型默认放在 rl_fishing/models，不随仓库提交，可自行重训。

## 运行

直接运行主程序：

```bash
uv run python main.py
```

F8 开始或暂停，F9 退出。F7 用来在 RL 与 PID 之间预切模式，切换要等到暂停或当前局结束才生效，避免钓鱼途中突然改变行为；F6 切换检测档位。默认控制模式写在 main.py 顶部的 CONTROL_MODE 全局变量里，默认检测模式由 DETECT_MODE 控制，两处都可以直接改代码后重启生效。

## 训练

YOLO 的训练数据在 yolo_dataset 目录，类别顺序为 bar(0)、fish(1)，入口是 train_yolo.py：

```bash
uv run python train_yolo.py
```

RL 策略的训练入口在 rl_fishing/train.py，默认参数已经包含 20Hz、噪声与延迟的随机化：

```bash
uv run python rl_fishing/train.py --timesteps 200000
```

想了解当前 PDM-PID 在模拟环境中的水平，可以运行 rl_fishing/test_pid_gym.py 查看各难度下的胜率和准度。

## 已知限制

游戏进度条还没有读取，RL 观测里的 progress 是固定估计值，所以策略并不清楚是否接近胜利。训练只覆盖了钓鱼等级 0，等级变化会改变条的长度，策略不一定跟得上。真实机器在十七到二十帧左右时，控制效果会明显变差，而模拟器在 60Hz 与 20Hz 下的差距本身就很大。cv 模式的鱼模板只对同一种外观的鱼有效，换鱼种容易漏检。此外 ROI 和模板参数依赖固定分辨率与窗口布局，换环境基本要重新校准。
